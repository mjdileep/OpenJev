Method and limitations

SemIf scores one prompt listing all moves and reads the answer-letter logits. Both receive identical strategy instructions and exact one-step previews. Neither uses search or a fallback policy. Forced moves are applied directly for both and excluded from inference timings.

Latency comes from the same frozen boards, with a full warm-up and alternating method order. Full-game scores use paired random seeds, but different actions change available spawn positions. This single-question workload does not test multi-question caching.

Both run on SemIf’s pinned MLX-LM 0.32.0 revision containing a Qwen3.5 normalization fix. OpenJev’s normal dependency range is below 0.32; this comparison uses an isolated shared environment. The protocol records source hashes and any local modifications. No claim compares the projects’ different default installations.
